# Design

## Overview

图书进销存管理系统采用产品型后台界面规范。设计服务于库存、订单和图书数据操作，不承担品牌营销表达。

默认场景：管理员在日间办公环境中使用桌面浏览器处理入库、订单和库存数据；普通用户在同一系统中完成图书选择和下单。界面应使用浅色、低干扰、信息清楚的管理系统风格。

## Visual Direction

整体策略是 restrained product UI。以浅灰背景、白色内容面、清晰边框、Element Plus 控件和有限主色构成界面。主色只用于主操作、当前导航、选中态和信息状态，不作为大面积装饰。

不得使用夸张渐变、复杂动画、装饰性背景、营销型大标题、玻璃拟态或过度阴影。

## Color Tokens

当前界面已有基础色：页面背景 `#f5f7fb`、登录背景 `#eef2f7`、文本 `#1f2937`、边框 `#e5e7eb`、白色内容面 `#ffffff`。后续改造应先把这些集中为 CSS 变量，再逐步替换内联样式。

| Token | Value | Usage |
| --- | --- | --- |
| `--color-bg` | `#f5f7fb` | 应用主背景 |
| `--color-bg-muted` | `#eef2f7` | 登录页、次级背景 |
| `--color-surface` | `#ffffff` | 顶栏、表格、弹窗、表单容器 |
| `--color-border` | `#e5e7eb` | 分隔线、表格边框、面板边界 |
| `--color-text` | `#1f2937` | 正文、表格主文本、标题 |
| `--color-text-muted` | `#64748b` | 辅助说明、弱化元信息 |
| `--color-primary` | `#2563eb` | 主操作、当前导航、焦点强调 |
| `--color-success` | `#16a34a` | 成功、上架、发货完成 |
| `--color-warning` | `#d97706` | 警告、待处理、下架操作 |
| `--color-danger` | `#dc2626` | 删除、失败、危险操作 |

Element Plus 默认语义色可以继续使用，但页面自定义样式应向上述 token 收敛。辅助文字不要低于 4.5:1 对比度。

## Typography

继续使用适合中文管理系统的单一无衬线字体栈：

```css
font-family: Arial, "Microsoft YaHei", sans-serif;
```

推荐固定字号，不使用随视口缩放的标题。

| Role | Size | Weight | Usage |
| --- | --- | --- | --- |
| Page title | `22px` | `600` | 页面一级标题，如图书管理、订单管理 |
| Section title | `18px` | `600` | 表单分组、弹窗内重点分区 |
| Body | `14px` | `400` | 表格、表单、按钮、正文 |
| Meta | `13px` | `400` | 次要说明、辅助状态 |

标题保持短句，不做全大写、字距拉开或营销式文案。

## Layout

管理端保留左侧导航和顶部栏结构。侧边栏宽度维持 `220px`，顶部栏高度维持 `56px`。内容区使用 `.page` 容器，桌面端默认内边距 `20px` 至 `24px`。

用户端保留顶部水平导航。图书列表、购物车和订单页继续以表格为核心，不引入独立营销首页。

工具栏使用横向 flex 布局，允许换行，控件间距 `12px`。筛选控件宽度应按字段含义稳定设置，不因 placeholder 或数据变化跳动。

表格页面优先保证 1366px 宽度下可扫描。移动端或窄屏后续可使用横向滚动、折叠筛选或关键列优先显示，不通过缩小字体解决拥挤。

## Components

### App Shell

顶部栏承载系统名称、当前用户和退出操作。管理端侧边栏承载全部后台模块，不新增隐藏式导航。

当前导航状态要清楚，颜色和字重可以共同表达。侧边栏品牌区不使用大 logo 或装饰图形。

### Toolbars

筛选项在左，查询和新增等操作跟随其后。主操作使用 `type="primary"`；新增也可使用 primary 或 success，但同一页面中主操作优先级必须清楚。

不要把每个工具栏包成独立卡片。页面背景和表格面已经足够形成层级。

### Tables

表格是核心组件。继续使用 Element Plus `el-table`，列宽保持稳定，金额、库存、状态、时间和操作列应有明确宽度。

操作列按钮顺序遵循：查看或修改、状态切换、危险操作。危险操作使用 danger，不和普通操作同色。

订单明细的展开表格可以保留，但嵌套表格应弱化边框或间距，避免与主表格视觉重量相同。

### Forms

表单标签宽度按页面维持稳定：常规弹窗 `90px`，入库页面 `100px`。数字输入使用 `el-input-number`，金额输入保留精度设置。

表单容器不需要重阴影。独立表单页可使用最大宽度限制，如 `560px`，并保持左对齐。

### Dialogs

弹窗用于新增、编辑和提交订单等短流程。宽度保持当前范围：分类约 `420px`，订单约 `460px`，图书约 `620px`。

弹窗底部操作保持取消在左、确认在右。确认按钮文案应说明动作，如保存、确认下单。

### Status

订单状态、图书上下架、库存变动类型应逐步从纯文本升级为统一的状态标签。状态标签使用低饱和背景和深色文字，不使用满版高饱和色块。

### Empty And Loading States

列表为空时应给出与页面相关的空态，例如暂无图书、暂无购物车商品、暂无订单记录。加载状态优先使用表格骨架或 Element Plus loading，不在内容中央长期显示孤立 spinner。

## Motion

产品界面只使用状态型动效：hover、focus、菜单选中、弹窗打开、加载反馈。时长控制在 `150ms` 至 `200ms`。

新增动效必须包含：

```css
@media (prefers-reduced-motion: reduce) {
  * {
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

## Implementation Guidelines

优先保留 Element Plus 组件和现有 Vue 结构。后续视觉修改应从 `src/style.css` 中抽取全局 token 和通用类开始，再逐页替换内联样式。

不得改变 `src/router/index.js` 的路由层级和管理员权限判断。不得改变 `src/utils/request.js` 的接口基地址、Cookie、响应解包和错误提示语义。不得改变 `src/utils/auth.js` 的本地用户存储 key 和读写函数语义。

后续建议按小范围提交推进：先统一全局 token 和布局，再处理管理端表格页，最后处理登录注册和用户端购买流程。每次改动后运行 `npm run build` 验证。
